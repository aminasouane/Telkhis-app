💌 رسالة إلى المطور — تنفيذ المعمارية الآمنة (Secure Architecture Implementation)

مرحبًا 👋

بعد مراجعة بنية المشروع الحالية، قررنا المضي قدمًا في تنفيذ المعمارية الآمنة الكاملة بدل الاعتماد على الحل المؤقت.
الهدف من هذه المهمة هو جعل تطبيق تلخيصلي (Takhleesly) جاهزًا تمامًا للإطلاق التجاري، مع حماية كاملة للبيانات والمستخدمين.

🎯 هدف المهمة

تنفيذ نظام دخول وتجربة آمنة (Secure Backend-Mediated Soft Authentication & Trial System)
بحيث يتم التحكم الكامل في صلاحيات المستخدمين، فترات التجربة، والتلخيصات من الخادم فقط.

🧱 المهام المطلوبة
1. الخادم (Backend Layer)

إنشاء طبقة خادم تستخدم مفتاح الخدمة SUPABASE_SERVICE_ROLE_KEY من متغيرات البيئة فقط.

كل عمليات Supabase (إضافة مستخدمين، تلخيصات، اشتراكات، تحقق تجريبي) يجب أن تتم من خلال هذه الطبقة.

إنشاء واجهات API التالية:

POST /api/guest-session
GET /api/trial-status
POST /api/save-summary
GET /api/summaries
DELETE /api/summaries/:id
POST /api/migrate-guest


إضافة Middleware للتحقق من التوكن وفترة التجربة قبل أي عملية تلخيص.

2. قاعدة البيانات (Supabase)

تفعيل Row Level Security (RLS) على جميع الجداول.

إنشاء سياسات “المالك فقط” بحيث لا يمكن لأي مستخدم الوصول إلى بيانات غيره.

إضافة RPC function (وظيفة إجرائية) لزيادة عدّاد التلخيصات بشكل ذري لتجنّب التداخل (race condition).

3. الواجهة الأمامية (Frontend)

إزالة أي عمليات supabase.from() مباشرة من كود React.

استبدالها بطلبات fetch() إلى واجهات الـ API التي سيتم إنشاؤها.

عند فتح التطبيق، يبدأ المستخدم مباشرة كـ "ضيف" دون تسجيل دخول.

عند انتهاء التجربة، يظهر له تنبيه أو نافذة تسجيل للدخول (Soft Onboarding Flow).

4. إعداد المفاتيح في Replit

أضيف القيم التالية في Secrets:

SUPABASE_URL = https://gsgrmojedoqvqccehnxl.supabase.co
SUPABASE_SERVICE_ROLE_KEY = (القيمة الجديدة من Supabase)


تأكد من أن المفاتيح تُستخدم فقط داخل ملفات الخادم (/api/)
ولا تظهر نهائيًا داخل كود React في src/.

✅ شروط الإنجاز (Definition of Done)

جميع العمليات الحساسة تمر عبر الخادم فقط.

RLS مفعّلة على قاعدة البيانات، مع سياسات المالك.

تجربة المستخدم التجريبية (Trial) يتم التحقق منها على الخادم قبل المعالجة.

يعمل تدفق المستخدم: ضيف → نهاية التجربة → ترقية أو تسجيل دخول دون فقدان البيانات.

لا توجد استدعاءات مباشرة لـ Supabase من الواجهة الأمامية.

تم اختبار العملية بنجاح (إنشاء ملخص، انتهاء تجربة، تسجيل دخول، ترحيل البيانات).

⏱️ المدة التقديرية

حوالي 2 إلى 3 ساعات من العمل المركز، تشمل الاختبار والتوثيق.
